# Native JSON-schema comparison

Separate operational baseline, prepared before native benchmark inference. It is not pooled with the unconstrained format experiment.

200 requests: 50 TableBench numerical cases and 50 SOB OCR-text cases from the expanded study, with reasoning off/on. Same case seeds, messages, temperature, top_p, 32768-token cap and JSONAdapter parser as the expanded actual JSON arm. Only response_format is added. Its schema is generated by DSPy 3.3.1's installed _get_structured_outputs_response_format helper (source snapshotted), using the actual typed signature. No tool fields exist in these signatures. This measures the native-schema request path without invoking extra model fallback calls or full DSPy transport discovery.

The DSPy helper strengthens nested object schemas by requiring every declared property and forbidding additional properties. Reference compatibility is checked before inference. Eighteen encountered OCR candidates failed this stronger contract and were excluded to obtain 50 supported OCR cases; all exclusions are logged. This is a supported-subset comparison, not evidence that native decoding supports every schema in the full dataset. Compare against the exact same case IDs from the expanded unconstrained JSON and TOON arms, not their full-dataset means.

50 concurrent requests; run after the main batch. Latency across separately executed batches is descriptive, not a controlled speed comparison. Raw responses, reasoning, tokens, truncations, errors and all failures are retained. No retries or server changes. The two simple compatibility probes are separate and excluded from benchmark metrics; they ran while the main batch was active.

The response_format json_schema API is documented at https://docs.vllm.ai/en/stable/features/structured_outputs . JSONAdapter formatting and parsing are documented at https://dspy.ai/diving-deeper/adapters/ . A successful schema-mode response can still contain an incorrect answer, and budget exhaustion can still prevent a final answer.

Data/scorer provenance and licensing: ../qwen_20260905/ and ../qwen_blog_expanded/PROTOCOL.md. The frozen native requests retain the expanded study's case indexes and seeds. No performance-based case selection or prompting changes were made.

All 18 encountered native-compatibility exclusions were missing properties that the original schema treated as optional but DSPy's generated native schema made required (for example notes or email). They were not excluded for low model accuracy. The source reference answers were not modified to fill those fields.
